# Запуск (Я запускал через venv)

1. Установить зависимости:

```bash
pip install -r requirements.txt
```

2. Заполнить `.env` по примеру `.env.example`.

Обязательные данные для основных тестов:

```env
USER_USERNAME=
USER_PASSWORD=
```

Для параметризованной проверки ролей можно дополнительно заполнить:

```env
MODERATOR_USERNAME=
MODERATOR_PASSWORD=
ADMIN_USERNAME=
ADMIN_PASSWORD=
```

Если данные модератора или администратора не указаны, соответствующий параметризованный кейс будет пропущен.

3. Запустить тесты:

```bash
pytest -v
```
# Список тестов

- Успешная авторизация пользователя.
- Параметризованная негативная авторизация:
  - неверный пароль;
  - несуществующий пользователь;
  - пустой username;
  - пустой password.
- Получение профиля авторизованного пользователя.
- Получение профиля без токена.
- Верификация валидного токена.
- Верификация токена без токена.
- Параметризованная проверка входа и профиля для ролей `user`, `moderator`, `admin`.
- Параметризованная проверка доступа к чужим профилям по ролевой модели:
  - `user` не может открыть профиль `admin`;
  - `admin` может открыть профиль `user`;
  - `moderator` может открыть профиль `user`, если заполнены данные модератора.
- Проверка списка профилей `GET /api/profiles/`:
  - `user` не видит чужие профили;
  - `admin` видит профиль пользователя и администратора.
- Проверка смены роли `PUT /api/profiles/{account_id}/role`:
  - `user` не может изменить собственную роль;
  - `admin` может изменить роль пользователя, после чего тест возвращает исходную роль обратно.

# Пояснение по функциям

- `test_user_can_login` - проверяет успешный логин пользователя, наличие `access_token` и тип токена `bearer`.
- `test_user_cannot_login_with_invalid_credentials` - параметризованный тест негативного логина. Проверяет статус `401` и текст ошибки `Incorrect username or password` для неверного пароля, несуществующего пользователя, пустого username и пустого password.
- `test_authorized_user_can_get_profile` - проверяет, что пользователь с валидным токеном может получить свой профиль.
- `test_user_cannot_get_profile_without_token` - проверяет, что эндпоинт профиля закрыт для запроса без токена, статус `403` и текст ошибки `Not authenticated`.
- `test_user_token_can_be_verified` - проверяет, что валидный токен пользователя подтверждается через `/api/auth/verify`.
- `test_token_cannot_be_verified_without_token` - проверяет, что `/api/auth/verify` не работает без токена, статус `403` и текст ошибки `Not authenticated`.
- `test_role_can_login_and_get_own_profile` - параметризованный тест: по очереди проверяет логин, получение профиля, `username` и роль для `user`, `moderator`, `admin`.
- `test_role_access_to_profiles` - параметризованный тест ролевой модели. Сначала получает account id целевого пользователя через `/api/profiles/me`, затем проверяет доступ к `/api/profiles/{account_id}` от имени другой роли.
- `test_user_list_profiles_does_not_return_foreign_profiles` - проверяет, что обычный пользователь не получает чужие аккаунты в списке профилей.
- `test_admin_list_profiles_contains_user_and_admin` - проверяет, что администратор видит в списке профилей и пользователя, и администратора.
- `test_user_cannot_change_own_role` - проверяет, что пользователь не может изменить свою роль, статус `403` и текст ошибки `Only administrators can change roles`.
- `test_admin_can_change_user_role_and_rollback` - проверяет, что администратор может изменить роль пользователя. После успешной смены тест обязательно возвращает исходную роль обратно.
